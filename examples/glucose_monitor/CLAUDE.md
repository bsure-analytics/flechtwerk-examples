# Glucose Monitor (`glucose`)

**Glucose Monitor** (`glucose`) is the personal-data case: a FreeStyle Libre 3's readings via **LibreLinkUp**, the follower side of Abbott's LibreView cloud — an **unofficial, reverse-engineered API** (paths, headers and shapes from `nightscout-librelink-up`'s type definitions, not measured: the fixture is **synthetic** and no real account has been polled yet, so the first live run is the verification still owed). `ingest` (an Extractor over the compacted `glucose-accounts` topic, one record per LibreLinkUp *follower* account keyed by an operator slug) is **a backup, not a parser**: per poll it lists `/llu/connections` (the patient ids — the one body read, flagged) and emits each `/llu/connections/{patientId}/graph` response's **`data`** to `glucose-raw` as delivered (`{metadata, response}`, keyed by patient id), **never the envelope's `ticket`** — a renewed bearer token, the one part of a response that must not be backed up. It has **no cursor** (LibreLinkUp has no "since"; every poll replays a ~12 h window); its only state is the **session, `ENCRYPTED` whole** (`SESSION`, a custom `SESSION_CODEC` over the `client.Session` dataclass inside `ENCRYPTED`) — every secret is encrypted wherever it rests, so the changelog holds one `flenc:jwe:…` token and never the bearer token, account id, host or the (unsalted, hence secret) credentials `fingerprint` in the clear. The credential is a sign-in, not a key: email **and** password are `ENCRYPTED(STR)` on every account record (the TMDB shape; the email too, as personal data), `request-glucose account <slug> [region]` reads them from the tty (password via `getpass`) or two stdin lines — never argv — **signs in once to check** them (refusing to store what LibreView refuses), learns the region from the login redirect and stores it, and prints whom the account follows. The stage re-signs-in only `RENEW_BEFORE` (10 min) ahead of `expires`, when the credentials' `fingerprint` changed, or on a 401 (`client.SessionRejected` — the one failure it remedies itself, so a revoked session can't crash-loop) — signing in per poll or per restart would be a login a minute, which locks accounts; it yields `State` **only after a sign-in**, because encryption is randomized and the runner compares raw state, so re-yielding an unchanged session would be fresh ciphertext and a changelog write every poll. Renewed tickets in response envelopes are **ignored** (the sign-in's ticket serves until `expires`, as in the reference client) and never backed up. A retired account's encrypted session stays on the changelog until it expires. `client.py` holds the protocol (global host `api.libreview.io` → `{"redirect": true, "region": …}` → `REGION_HOSTS`; `account-id` = SHA-256 hex of the user id, demanded since 2025; `product`/`version` headers that must track an accepted app version — bump `VERSION` when sign-in breaks; status 4 = a `data.step` the app wants done, e.g. `tou`), and `LoginRefused` names the remedy (`request-glucose account <slug>`) without echoing a credential. `readings` (a Transformer, state key = patient id) is the first stage to read a response: `projection.readings` takes the connection's `glucoseMeasurement` (`kind = live`, ~1/min, with `TrendArrow`) and every `graphData` point (`kind = history`, coarser, no arrow), parses LibreLinkUp's US `M/D/YYYY h:mm:ss AM` by regex (not `strptime`'s locale-bound `%p`), takes `FactoryTimestamp` as UTC and `Timestamp` as the phone's local clock — their difference, rounded to 15 min, is `utc_offset_min`, which the daily profile groups by — and spreads the item through as delivered beside the computed `patient_id`/`kind`/`measured_at`/`utc_offset_min`/`fetched_at`. `projection.fresh` keeps `SEEN = {kind: [epoch s]}` of the last **24 h of event time** behind the newest stamp (twice the window; ~20 KB, so no hard cap) — a seen-set, not a high-water mark, because LibreLinkUp fills history in *behind* the newest point. ClickHouse: one append-only `glucose_readings` (EOS + `read_committed` make each reading land once), `mg_dl Float64` (never an integer cast), `trend_arrow`/`utc_offset_min` `Nullable` (a missing arrow must not read as 1 = falling fast), `__time` ALIAS `measured_at`, **no TTL** (it is the only long history). The dashboard's statistics (mean, GMI, CV, time in the five consensus ranges, the 14-day profile by local hour, the per-day table) read `kind = 'history'` — gap-free across outages under 12 h and on a regular grid; the chart draws both kinds. It is health data: the README says keep the stack local and that this is not a medical device. Ports: `ingest` 9127, `readings` 9128.
